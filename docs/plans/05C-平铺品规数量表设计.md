# 阶段 5C：平铺品规数量表设计

**批准日期：** 2026-09-01
**状态：** 页面设计已批准，等待书面规格确认

## 1. 目标

将扫码工作台现有“标准名称分组—条码版本子表”改为一张直接可读的平铺表格，减少不常用的版本层级，使日常盘点人员能够在一行内核对品规、条码、价格、数量和金额。

## 2. 数据行规则

- 一行对应一个批次汇总项，即一个 `product_id` 和其扫码时品规快照；
- 重复扫描同一 `product_id` 时继续累计到原行；
- 同一标准名称对应不同 `product_id` 或不同条码时，显示为多条平级记录；
- 不再显示品规组标题、版本数量或版本子表；
- 各行继续使用自身品规快照中的条码、价格和条支比，数量与金额不跨行合并；
- 行顺序保持后端汇总项顺序，不新增排序或筛选规则。

页面说明文字固定为：“相同条码品规自动累计；同名称不同条码平级显示。”

## 3. 表格字段

| 顺序 | 列名 | 数据来源或显示规则 |
|---:|---|---|
| 1 | 序号 | 当前表格行号，从 1 开始 |
| 2 | 品牌 | `product_snapshot.brand` |
| 3 | 卷烟名称（标准品规） | `product_snapshot.standard_name` |
| 4 | 已扫描条码 | `product_snapshot.carton_code` |
| 5 | 条码后 6 位 | `carton_code` 最后 6 位 |
| 6 | 类型 | 固定显示“卷烟” |
| 7 | 条支比 | `product_snapshot.sticks_per_carton` |
| 8 | 零售价 | 该条码版本的 `carton_retail_price`；为空时显示“未维护” |
| 9 | 数量（条） | 现有最终条数，保留 `− / 输入 / + / 确认` 控件，步进固定为 0.1 条 |
| 10 | 金额小计 | 该行折合条数乘以该行条零售价 |
| 11 | 操作 | 固定显示 `—`，本次不实现删除 |

## 4. 交互与权限

- 操作员在 `DRAFT` 批次中继续使用现有 0.1 条增减和直接设置功能；
- VIEWER 或非 `DRAFT` 批次继续禁用数量控件；
- 调整请求继续针对该行 `product_id`，不改变后端 API、幂等或权限逻辑；
- 调整成功后使用后端权威状态刷新表格并恢复扫码输入焦点；
- 表格为空时继续显示明确空状态。

## 5. 视觉与响应式

- 表头采用紧凑政企风格，名称、条码和金额为主要视觉信息；
- 条码使用等宽字体，金额右对齐，数量控件保持可点击尺寸；
- 桌面端显示完整 11 列；窄屏使用横向滚动，不折叠成版本卡片；
- 不显示“导出统计”“CSV 导出”“清空盘点”按钮；
- 不显示删除按钮，操作列只保留占位符，后续功能批准后再增加。

## 6. 技术边界

本次只修改：

- `frontend/src/__tests__/scan-workspace.spec.ts` 和必要的展示测试；
- PRD、SPEC 和总体实施计划中的扫码表格说明。

本次不修改数据库、SQLAlchemy 模型、后端 API、扫码事务、数量调整规则、导出、清空、删除或完成批次功能。

## 7. 验收

1. 页面只有一层平铺表格，不出现版本组标题或版本子表；
2. 每个批次汇总项对应一行，同名称不同条码显示为平级行；
3. 11 列内容、价格、数量和金额对应当前行的品规快照；
4. 0.1 条增减、直接设置、权限禁用和扫码焦点恢复保持可用；
5. 导出、CSV、清空和删除入口均不显示；
6. 前端单测、ESLint、构建和真实 E2E 回归通过；
7. 没有后端、数据库或 DDL 变化，没有 Git 提交或推送。
