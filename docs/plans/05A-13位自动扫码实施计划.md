# 13 位键盘输入自动扫码实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 `executing-plans` 在当前会话逐任务执行；每个行为变更遵循 TDD 红—绿—重构。用户要求不提交或推送 Git，因此使用测试与 Git 状态检查点代替 commit。

**目标：** 扫码输入达到 13 位数字后立即自动识别，同时保持幂等重试、尾随回车去重和后端 13 位契约。

**架构：** 后端只收紧扫描批次的 `code` 校验，不修改品规表或导入规则。前端由扫码输入事件驱动统一的 `submitScan`，使用提交锁、最后尝试编码和现有 `request_id` 管理确定响应、网络重试和改码重试。

**技术栈：** FastAPI、Pydantic、SQLAlchemy、Vue 3、TypeScript、Vitest、pytest、Playwright。
