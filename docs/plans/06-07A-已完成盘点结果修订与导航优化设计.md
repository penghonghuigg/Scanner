# 阶段 6+7 补充：已完成盘点结果修订与导航优化设计

> 状态：业务设计已确认，等待用户书面审查后编写实施计划
> 设计日期：2026-09-02
> 适用项目：涉案卷烟智能统计系统

## 1. 背景与目标

当前“扫描批次”列表固定查询 `DRAFT`，导致已完成批次没有独立入口；人员注册页和品规管理页分别复制了不完整的侧栏，遗漏了批次菜单；阶段 6 的原设计又把 `COMPLETED` 批次设为完全只读，不能满足实际工作中修订最终盘点结果的需要。

本补充模块实现以下闭环：

```text
盘点作业（进行中）
  → 完成批次
  → 盘点结果（已完成）
  → 禁止继续扫码
  → 允许维护数量、来源地和结果品规
  → 按最新结果重新导出 Excel
```

同时调整外省卷烟来源规则：只知道来源省时允许市级保存为“不详”。

## 2. 已确认方案

采用方案 A：在左侧设置两个平级入口。

- `盘点作业`：只展示 `DRAFT` 批次，承载新建、扫码、异常处理和完成流程；
- `盘点结果`：只展示 `COMPLETED` 批次，承载查询、结果修订和 Excel 导出；
- 已完成批次始终保持 `COMPLETED`，不重新打开为 `DRAFT`，也不增加中间状态；
- 已完成批次关闭扫码和异常处理，但允许在权限范围内维护最终结果；
- 数据库表名、后端模型名和现有 `/api/v1/scan-sessions` 路径保持不变，界面文案按业务含义调整。

未采用方案：

- 折叠式“盘点管理”菜单：小型系统中会增加一次操作，收益有限；
- 单菜单内使用状态页签：不能满足左侧直接增加已完成结果入口的要求；
- 把批次重新打开为 `DRAFT`：会重新开放扫码，与用户要求冲突；
- 增加 `CORRECTING` 状态：需要额外数据结构和状态流转，当前规模没有必要。

## 3. 页面和导航设计

### 3.1 共用侧栏

新增共用侧栏组件，由首页、人员注册、品规管理、盘点作业和盘点结果页面共同使用，不再在各页面复制菜单。

菜单顺序：

1. 系统首页；
2. 盘点作业；
3. 盘点结果；
4. 人员注册，仅管理员显示；
5. 品规管理，仅管理员显示。

侧栏根据当前路由自动显示激活项。管理员进入人员注册或品规管理后，“盘点作业”和“盘点结果”仍保持可见。

### 3.2 盘点作业

- 路由继续使用 `/scan-sessions`；
- 列表固定查询 `status=DRAFT`；
- 保留批次编号、立案编号、地点等现有检索条件；
- 页面操作包括新建盘点作业、进入扫码和继续处理；
- 原“扫描批次”“新建扫描批次”等面向用户的文案相应改为“盘点作业”“新建盘点作业”。

### 3.3 盘点结果

- 新增路由 `/scan-results`；
- 列表固定查询 `status=COMPLETED`；
- 复用盘点作业列表的检索、分页、分局数据权限和展示组件；
- 点击记录进入已完成详情；
- 已完成详情沿用盘点工作台的统计布局，但不显示扫码输入、歧义处理和未知编码处理操作；
- 页面提供数量及来源维护、删除品规、从品规库添加和重新导出 Excel。

## 4. 已完成结果修订规则

### 4.1 状态边界

`COMPLETED` 仅表示现场扫码过程已经结束，不再表示结果完全不可修订。

允许的操作：

- 调整已有品规数量；
- 修改已有品规的来源地分配；
- 删除统计中的品规；
- 从基础库选择启用品规并加入结果；
- 下载按当前结果实时生成的 Excel。

禁止的操作：

- 扫码新增；
- 处理或重选歧义编码；
- 删除、覆盖原始扫码流水；
- 把批次恢复为 `DRAFT`。

### 4.2 数量和来源一致性

- 数量最小业务单位保持为 1 包，即固定 `0.1 条`；
- 数量不能小于 0，并必须满足整包对齐；
- 已完成批次修改数量时，数量和完整来源分配在同一个确认窗口提交，由后端在一个事务中保存，避免产生数量与来源暂时不一致的已完成结果；
- 只修改来源地时，来源分配的总数量必须等于品规当前数量；
- 删除品规时，把数量归零、从统计表隐藏，并同步清除该汇总项的当前来源分配；
- 原始扫码事件不删除，数量调整和删除继续追加 `ADJUST` 流水。

### 4.3 修改原因和操作记录

- 已完成批次的结果修订不要求操作员填写修改原因；
- 后端生成简短的系统原因，例如“已完成结果修订：设为 1.2 条”“已完成结果修订：删除品规”；
- 数量及删除流水记录操作人和操作时间；
- 来源分配记录保留最后修改人和最后修改时间；
- 本补充模块不新增独立的来源地历史流水表。

### 4.4 从品规库添加

- 搜索框支持输入标准品规名称或条形码后 6 位；
- 只返回 `is_active=true` 的基础库品规；
- 操作员不能输入并保存基础库中不存在的自由文本品规；
- 选中品规后必须同时填写加入数量和完整来源分配；
- 加入数量最小为 `0.1 条`；
- 第一次加入时复制当前品规信息到 `scan_session_items.product_snapshot`，保存历史快照；
- 如果同一条码品规已经存在，则不创建重复汇总行，而是在现有数量上累计本次加入数量，并按来源组合合并本次来源分配；
- 手工加入使用唯一 `request_id` 保证重复提交不重复累计。

## 5. 外省来源地规则调整

来源类型继续使用现有四类，只修改 `OUTSIDE_PROVINCE` 的市级规则。

| 来源类型 | 省 | 市 |
|---|---|---|
| 外省流入 `OUTSIDE_PROVINCE` | 必选，且不能是安徽省 | 可选；默认并允许保存为“不详” |
| 来源不详 `UNKNOWN` | 空 | 空 |
| 市内串码 `LOCAL_HUAINAN` | 固定安徽省 | 固定淮南市 |
| 省内市外 `ANHUI_OTHER_CITY` | 固定安徽省 | 必选，且不能是淮南市 |

补充规则：

- 外省城市下拉框首项固定为“不详”；
- 选择或切换外省省份后，市默认重置为“不详”；
- 北京市、天津市、上海市和重庆市也允许保存为“直辖市名称 + 不详”；
- 选择具体城市时仍必须属于所选省级地区；
- 香港特别行政区和澳门特别行政区继续排除；
- Excel 中外省市级未明确时显示“不详”，不留空。

## 6. 权限设计

| 用户 | 可见范围 | 盘点作业 | 盘点结果修订 |
|---|---|---|---|
| 管理员 | 全部分局及管理员创建的记录 | 可操作 | 可操作 |
| 业务操作员 | 本分局业务人员创建的记录 | 可操作 | 可共同维护 |
| 只读用户 | 现有数据范围 | 只读 | 只读 |

细则：

- 同一县分局内，不限制只能由批次创建人修订，允许本分局业务操作员共同维护；
- 分局用户不能查看或修改其他分局记录；
- 分局用户不能查看或修改管理员创建的记录；
- 所有写接口继续校验登录状态、角色、数据范围和可信来源。

## 7. API 契约设计

### 7.1 列表与详情

继续复用：

```http
GET /api/v1/scan-sessions?status=DRAFT
GET /api/v1/scan-sessions?status=COMPLETED
GET /api/v1/scan-sessions/{session_id}
GET /api/v1/scan-sessions/{session_id}/scan-state
```

列表和详情继续使用现有分局数据范围。`scan-state` 对已完成批次只返回数据，不代表允许扫码。

### 7.2 轻量品规检索

新增：

```http
GET /api/v1/product-options?query={name_or_last_six}&page=1&page_size=20
```

规则：

- 所有已登录用户均可查询，未登录返回 401；
- 只返回启用品规；
- 按标准品规名称或条形码后 6 位匹配；
- 返回最小必要字段：`id`、`carton_code`、`brand`、`standard_name`、`carton_retail_price`、`sticks_per_pack`、`packs_per_carton`；
- 不改变 `/api/v1/products` 管理接口仅管理员可用的规则。

### 7.3 已完成结果手工加入

新增：

```http
POST /api/v1/scan-sessions/{session_id}/result-items
```

请求字段：

- `request_id: string`；
- `product_id: integer`；
- `quantity_cartons: decimal`，最小 `0.1` 且只能按 `0.1` 递增；
- `source_allocations: array`，结构复用现有来源分配项。

后端在一个事务中完成批次行锁、幂等检查、品规快照、汇总数量、`ADJUST` 流水和来源分配。

### 7.4 已完成结果修改

新增：

```http
PUT /api/v1/scan-sessions/{session_id}/result-items/{product_id}
```

请求字段：

- `request_id: string`；
- `quantity_cartons: decimal`；
- `source_allocations: array`。

数量与来源在一个事务中替换。只修改来源时仍提交当前完整数量，确保结果一致。

### 7.5 删除、扫码和导出

- 现有品规删除接口允许在权限范围内处理 `DRAFT` 和 `COMPLETED`；
- 删除已完成品规时同步清除其当前来源分配；
- `/scan` 和 `/resolve` 对 `COMPLETED` 继续返回 `409 SCAN_SESSION_CLOSED`；
- Excel 继续以内存方式实时生成，不把文件保存到服务器；
- 每次下载读取最新汇总和来源数据，因此修订后重新下载即可获得最新结果。

## 8. 错误处理

| 场景 | HTTP | 错误码 |
|---|---:|---|
| 批次不存在或不在可见范围 | 404 | `SCAN_SESSION_NOT_FOUND` |
| 当前角色不能修订结果 | 403 | `FORBIDDEN` |
| 对已完成批次提交扫码或歧义处理 | 409 | `SCAN_SESSION_CLOSED` |
| 品规不存在或已停用 | 404/409 | `PRODUCT_NOT_FOUND` / `PRODUCT_INACTIVE` |
| 数量不是整包或小于最小值 | 422 | `QUANTITY_NOT_PACK_ALIGNED` |
| 来源总量与品规数量不一致 | 422 | `SOURCE_QUANTITY_MISMATCH` |
| 外省省市组合不合法 | 422 | `SOURCE_LOCATION_INVALID` |
| 同一 `request_id` 对应不同请求 | 409 | `IDEMPOTENCY_CONFLICT` |

前端必须显示后端业务提示，提交失败时保留用户尚未保存的输入，不静默吞掉错误。

## 9. 数据库影响

本模块不新增表、不增加字段、不修改索引，不需要执行建表或改表 SQL。

复用现有表：

- `scan_sessions`：状态和权限范围；
- `scan_session_items`：当前汇总及历史品规快照；
- `scan_events`：追加数量调整、删除和手工加入流水；
- `scan_item_source_allocations`：当前来源分配、最后修改人和时间；
- `cigarette_products`：已启用品规检索；
- `export_records`：下载行为记录，不保存 Excel 文件。

MySQL 命名卷 `scanner_mysql_data` 和现有持久化方式不变。

## 10. 测试与验收

按测试驱动方式先编写失败测试，再实现最小改动。

### 10.1 后端

- `DRAFT` 和 `COMPLETED` 列表过滤及现有分局数据范围；
- 管理员可修订所有结果，本分局操作员可共同修订，跨分局及管理员记录不可见；
- 只读用户不能修订；
- 已完成批次扫码和歧义处理仍被拒绝；
- 已完成数量及来源原子修改；
- 删除后统计隐藏、来源清除、原始扫码流水保留；
- 品规名称和条形码后 6 位检索，只返回启用品规；
- 手工加入的品规快照、数量、来源、幂等和并发累计；
- 外省城市“不详”的默认、校验、返回和 Excel 展示；
- 修订后 Excel 与最新数据库汇总一致。

### 10.2 前端

- 首页、人员注册、品规管理、盘点作业和盘点结果均显示完整共用侧栏；
- 管理员菜单与普通用户菜单按角色正确显示；
- 盘点作业只加载 `DRAFT`，盘点结果只加载 `COMPLETED`；
- 已完成详情隐藏扫码与异常处理操作；
- 品规名称及条形码后 6 位联想检索；
- 添加品规时同时提交数量和来源；
- 修改数量时同时核对来源；
- 外省城市默认为“不详”；
- 只读用户的修订操作不可用。

### 10.3 端到端闭环

```text
登录
  → 进入盘点结果
  → 检索并打开已完成批次
  → 按名称或条码后 6 位选择品规
  → 填写数量和来源后加入
  → 修改已有品规数量和来源
  → 删除一个品规
  → 重新导出 Excel
```

验收时同时验证刷新页面后数据仍存在，以及前后端字段与 SPEC 一致。

## 12. 范围外事项

- 不恢复已完成批次的扫码能力；
- 不撤销完成、不作废批次、不新增批次状态；
- 不允许录入基础库之外的临时品规；
- 不增加强制修改原因；
- 不增加独立的来源地历史流水表；
- 不修改案件基本信息；
- 不保存 Excel 文件到服务器；
- 不引入数据库迁移框架、Redis、消息队列或微服务。
