# 阶段 9：生产容器化与服务器部署实施计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将当前 Vue、FastAPI 和 MySQL 系统制作成可发布的生产 Docker Compose，在不影响服务器现有 Caddy 和其他容器的前提下，通过公网 IP HTTPS 上线，并初始化全新数据库、管理员和卷烟品规。

**架构：** 现有 Caddy 保持公网 80/443 唯一入口，通过独立外部网络 `scanner_proxy` 访问 `scanner-web`；`scanner-web` 提供 Vue 静态文件并将 `/api/` 转发到 `scanner-api`；API 与 MySQL 只连接内部网络 `scanner_internal`。MySQL 使用命名卷 `scanner_mysql_data`，真实配置存放在服务器 `/opt/scanner/config/.env`，服务器按固定 Git 标签构建和运行。

**技术栈：** Docker Compose、Caddy 2.11、Nginx 1.27 Alpine、Node 22 Alpine、Python 3.12 Slim、FastAPI、Vue 3、MySQL 8.4、PowerShell、Bash。

## 一、文件结构与职责

### 新建文件

- `.dockerignore`：缩小构建上下文并排除秘密、缓存、参考资料和生成文件。
- `.env.production.example`：生产配置字段契约，只保留非秘密默认值和空秘密项。
- `backend/Dockerfile`：构建非 root FastAPI 生产镜像。
- `frontend/Dockerfile`：多阶段构建 Vue，并生成只包含 Nginx 和静态文件的生产镜像。
- `deploy/nginx/nginx.prod.conf`：SPA、API 代理、登录限速、安全头和健康检查。
- `compose.prod.yaml`：生产 Web、API、MySQL、网络、卷、健康检查和日志轮转。
- `deploy/scripts/backup_mysql.sh`：月度及升级前 MySQL 备份、压缩校验和保留 12 份。
- `deploy/scripts/restore_mysql.sh`：只允许恢复到明确指定的隔离数据库。
- `deploy/cron/scanner-monthly-backup`：每月 1 日执行备份。
- `docs/deployment/生产服务器部署手册.md`：服务器准备、Caddy、初始化、验收、更新和回滚操作手册。

### 修改文件

- `.gitignore`：忽略生产 `.env`、品规数据转储、部署临时文件和本地备份。
- `frontend/playwright.config.ts`：允许通过 `PLAYWRIGHT_BASE_URL` 指定生产或验收地址，默认值保持本地开发地址。
- `docs/plans/00-系统分阶段实施计划.md`：全部验收完成后记录阶段 9 实施结果。

### 保持不变

- `compose.dev.yaml` 和 `deploy/nginx/nginx.dev.conf`：继续服务 Windows 本地开发，不改成生产用途。
- `references/`：用户原始资料不移动、不删除、不进入镜像。
- 数据库启动行为：应用启动不执行 DDL，继续显式运行 `app.cli.init_db`。

- [ ] **步骤 2：实现备份脚本**

脚本必须使用：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
umask 077

scanner_root="${SCANNER_ROOT:-/opt/scanner}"
compose_file="${scanner_root}/app/compose.prod.yaml"
env_file="${scanner_root}/config/.env"
backup_dir="${scanner_root}/backups"
timestamp="$(date -u +%Y%m%d-%H%M%S)"
target="${backup_dir}/scanner-${timestamp}.sql.gz"
temporary="${target}.tmp"

mkdir -p "${backup_dir}"
trap 'rm -f "${temporary}"' EXIT

docker compose --env-file "${env_file}" -f "${compose_file}" exec -T scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump -uroot --single-transaction --routines --triggers --events "$MYSQL_DATABASE"' \
  | gzip -9 > "${temporary}"

test -s "${temporary}"
gzip -t "${temporary}"
mv "${temporary}" "${target}"
trap - EXIT

mapfile -t old_backups < <(find "${backup_dir}" -maxdepth 1 -type f -name 'scanner-*.sql.gz' -printf '%T@ %p\n' | sort -rn | tail -n +13 | cut -d' ' -f2-)
if ((${#old_backups[@]} > 0)); then
  rm -f -- "${old_backups[@]}"
fi

printf 'backup_created=%s\n' "${target}"
```

删除范围只允许匹配 `/opt/scanner/backups/scanner-*.sql.gz`，不得使用宽泛目录或 `rm -rf`。

- [ ] **步骤 3：实现隔离恢复脚本**

`restore_mysql.sh` 使用以下完整边界：

```bash
#!/usr/bin/env bash
set -Eeuo pipefail
umask 077

if (($# != 2)); then
  printf '用法: %s /absolute/path/backup.sql.gz isolated_database\n' "$0" >&2
  exit 2
fi

backup_file="$(realpath -- "$1")"
restore_database="$2"
scanner_root="${SCANNER_ROOT:-/opt/scanner}"
compose_file="${scanner_root}/app/compose.prod.yaml"
env_file="${scanner_root}/config/.env"

if [[ ! -f "${backup_file}" || "${backup_file}" != *.sql.gz ]]; then
  printf '备份文件不存在或扩展名错误\n' >&2
  exit 2
fi
if [[ ! "${restore_database}" =~ ^[A-Za-z0-9_]+$ ]]; then
  printf '隔离数据库名只允许字母、数字和下划线\n' >&2
  exit 2
fi

gzip -t "${backup_file}"

production_database="$(docker compose --env-file "${env_file}" -f "${compose_file}" exec -T scanner-mysql printenv MYSQL_DATABASE | tr -d '\r')"
if [[ "${restore_database}" == "${production_database}" ]]; then
  printf '拒绝覆盖正式数据库\n' >&2
  exit 2
fi

if docker compose --env-file "${env_file}" -f "${compose_file}" exec -T scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -Nse "SHOW DATABASES"' \
  | tr -d '\r' | grep -Fxq "${restore_database}"; then
  printf '隔离数据库已存在，拒绝覆盖\n' >&2
  exit 2
fi

printf 'CREATE DATABASE `%s` CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;\n' "${restore_database}" \
  | docker compose --env-file "${env_file}" -f "${compose_file}" exec -T scanner-mysql \
      sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot'

gzip -cd -- "${backup_file}" \
  | docker compose --env-file "${env_file}" -f "${compose_file}" exec -T \
      -e RESTORE_DATABASE="${restore_database}" scanner-mysql \
      sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$RESTORE_DATABASE"'

docker compose --env-file "${env_file}" -f "${compose_file}" exec -T \
  -e RESTORE_DATABASE="${restore_database}" scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot -Nse "SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA = '\''$RESTORE_DATABASE'\''"'
```

脚本只创建隔离数据库，不包含删除数据库逻辑；测试库清理由上线验收时在明确确认库名后单独执行。
