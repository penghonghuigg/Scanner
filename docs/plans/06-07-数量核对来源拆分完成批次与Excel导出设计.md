# 阶段 6+7：数量核对、来源拆分、完成批次与 Excel 导出设计

> 状态：已完成业务设计，等待用户批准书面规格后编写实施计划。
> 适用项目：涉案卷烟智能统计系统。
> 设计日期：2026-09-02。

## 1. 目标与范围

本模块合并实施原阶段 6“数量核对、调整与完成批次”和阶段 7“Excel 导出”，并增加卷烟来源地拆分能力，形成以下业务闭环：

```text
扫码累计
 → 按 0.1 条核对和调整数量
 → 为每个条码品规分配来源地
 → 确认异常并完成批次
 → 已完成批次只读
 → 即时生成并下载 Excel
```

本模块继续采用适合约 50 名内网用户的 FastAPI + Vue + MySQL 单体架构，不引入数据库迁移框架、任务队列或文件存储服务。

## 2. 已确认业务规则

### 2.1 数量规则

- 数量核对、人工调整和来源拆分统一以 1 包为最小单位，即固定 `0.1 条`；
- 暂不支持单支调整；
- 页面可以显示包数、折合条数和支数，后端以整数包数和整数支数执行权威校验；
- 每个品规的每包支数从 `scan_session_items.product_snapshot` 读取，历史批次不依赖后来变化的基础库；
- 每个品规全部来源记录的总支数必须与该品规最终 `total_sticks` 完全一致，否则不能完成批次；
- 任意调整后的总支数不得小于零，且必须保持整包对齐；
- 人工调整只追加 `ADJUST` 流水，不覆盖或删除原扫码流水。

### 2.2 人工调整原因

现有增加、减少和设置数量操作继续保留，但提交前必须选择或填写原因：

- 现场核对修正；
- 扫码录入纠错；
- 散包数量核对；
- 其他，选择后必须填写具体说明。

最终原因写入 `scan_events.reason`，不新增调整流水表。

### 2.3 来源地类型

来源类型及地区规则如下：

| 来源类型 | 内部值 | 省 | 市 |
|---|---|---|---|
| 外省流入 | `OUTSIDE_PROVINCE` | 必填且不能为安徽省 | 必填且必须属于所选省 |
| 来源不详 | `UNKNOWN` | 空 | 空 |
| 市内串码 | `LOCAL_HUAINAN` | 固定安徽省 | 固定淮南市 |
| 省内市外 | `ANHUI_OTHER_CITY` | 固定安徽省 | 必填且不能为淮南市 |

补充规则：

- 北京市、天津市、上海市、重庆市归入外省流入，省、市均使用直辖市名称；
- 排除香港特别行政区和澳门特别行政区；
- 保留台湾省，并使用“台湾省—台湾省”；
- 删除用户提供名单中的重复城市；
- 删除“山西省—山西省”“福建省—福建省”等无效占位数据；
- 地区数据由后端静态权威目录提供，前端通过 API 获取，不在数据库和前端各维护一份。

### 2.4 来源拆分

- 一个条码品规可以拆分为多条来源记录；
- 相同品规、相同来源类型、省和市的记录自动合并；
- 来源数量以正整数包保存，折合条数为 `pack_count / 10`；
- 支数为 `pack_count × sticks_per_pack`；
- 同名称不同条码仍是不同品规汇总项，分别分配来源；
- 删除 DRAFT 批次中的品规汇总项时，同步删除该汇总项尚未封存的来源分配；
- 完成批次后来源数据不可编辑。

### 2.5 异常与完成

- 未识别编码不计入卷烟数量，可以随批次完成并导出；
- 未解决歧义编码不计入卷烟数量，也可以随批次完成并导出；
- 存在任一异常时，完成确认框必须醒目标明未知和未解决歧义数量；
- 操作员必须勾选“我已知晓异常编码将随批次封存”后才能提交；
- 完成操作把批次从 `DRAFT` 改为 `COMPLETED` 并记录 `completed_at`；
- 完成后禁止扫码、数量调整、品规删除、来源编辑及歧义处理；
- 本模块不支持重新打开、撤销完成或作废批次。

## 3. 方案选择

采用独立来源分配表方案：

- 新增 `scan_item_source_allocations` 保存结构化来源分配；
- 新增 `export_records` 保存导出审计记录；
- 继续复用 `scan_sessions`、`scan_session_items` 和只追加的 `scan_events`；
- 不向现有表增加 JSON 字段，不通过事件动态重放来源状态。

该方案只新增两张表，不修改已有表，兼顾简单性、数据库约束、查询导出和后续罚没烟快照复用。

## 4. 数据模型

### 4.1 `scan_item_source_allocations`

一行代表一个批次品规的一种来源组合。

| 字段 | 类型建议 | 约束与含义 |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | 主键、自增 |
| `session_item_id` | `BIGINT UNSIGNED` | 关联 `scan_session_items.id` |
| `source_type` | `VARCHAR(32)` | 四种内部值之一 |
| `province_name` | `VARCHAR(50)` | 来源不详时为空 |
| `city_name` | `VARCHAR(80)` | 来源不详时为空 |
| `pack_count` | `INT UNSIGNED` | 正整数包数 |
| `quantity_sticks` | `INT UNSIGNED` | 正整数支数，由后端换算并校验 |
| `source_key` | `VARCHAR(200)` | 规范化内部去重键，不暴露给前端 |
| `created_by` | `BIGINT UNSIGNED` | 创建用户 |
| `updated_by` | `BIGINT UNSIGNED` | 最后修改用户 |
| `created_at` | `DATETIME(6)` | UTC 创建时间 |
| `updated_at` | `DATETIME(6)` | UTC 更新时间 |

约束和索引：

- `UNIQUE(session_item_id, source_key)`；
- `CHECK(pack_count > 0 AND quantity_sticks > 0)`；
- `CHECK(source_type IN (...))`；
- 按 `session_item_id` 建普通索引；
- `session_item_id` 使用 `ON DELETE CASCADE`，仅服务于 DRAFT 状态下现有品规删除行为；
- 用户外键使用 `ON DELETE RESTRICT`；
- InnoDB、`utf8mb4_0900_ai_ci`。

`source_key` 规范：

```text
OUTSIDE_PROVINCE|省名|市名
UNKNOWN||
LOCAL_HUAINAN|安徽省|淮南市
ANHUI_OTHER_CITY|安徽省|市名
```

### 4.2 `export_records`

Excel 在内存中即时生成并直接下载，不保存到服务器文件系统。该表只记录导出行为和文件摘要。

| 字段 | 类型建议 | 约束与含义 |
|---|---|---|
| `id` | `BIGINT UNSIGNED` | 主键、自增 |
| `session_id` | `BIGINT UNSIGNED` | 关联已完成批次 |
| `filename` | `VARCHAR(180)` | 本次下载文件名 |
| `file_size` | `BIGINT UNSIGNED` | 生成内容字节数 |
| `file_sha256` | `CHAR(64)` | 文件内容 SHA-256 |
| `template_version` | `VARCHAR(20)` | 模板版本 |
| `generated_by` | `BIGINT UNSIGNED` | 导出用户 |
| `created_at` | `DATETIME(6)` | UTC 导出时间 |

索引和约束：

- 按 `session_id, created_at` 建索引；
- 批次和用户外键均使用 `ON DELETE RESTRICT`；
- InnoDB、`utf8mb4_0900_ai_ci`。

### 4.3 数据库实施约束

- 不使用 Alembic；
- 应用启动不执行 DDL；
- 两张新表通过明确 SQL 人工创建；
- 执行前备份数据库并由用户逐次批准 SQL；
- `init_db` 只用于空库创建缺失表及结构校验，不修改已有表；
- 不执行 `docker compose down -v`，继续使用 `scanner_mysql_data` 命名卷。

## 5. 后端接口

所有接口沿用 `/api/v1`、Cookie 鉴权、统一响应信封、权限范围和 `trace_id`。

### 5.1 地区目录

```text
GET /api/v1/regions
```

返回清理后的省市列表及四种来源类型。地区目录由后端维护，前端只消费返回值。

### 5.2 查询来源分配

```text
GET /api/v1/scan-sessions/{session_id}/source-allocations
```

返回当前批次所有品规的最终数量、已分配数量和来源明细。管理员可查看全部分局，其他角色遵循批次可见范围。

### 5.3 保存单个品规来源

```text
PUT /api/v1/scan-sessions/{session_id}/items/{product_id}/source-allocations
```

请求一次提交该品规的完整来源列表。后端在事务中：

1. 锁定批次和品规汇总；
2. 校验批次为 `DRAFT` 且用户有写权限；
3. 规范化和合并相同来源；
4. 校验地区组合、正整数包数和换算支数；
5. 校验所有来源总支数等于当前品规 `total_sticks`；
6. 替换该品规的来源集合；
7. 返回最新权威分配结果。

### 5.4 人工数量调整

继续使用：

```text
POST /api/v1/scan-sessions/{session_id}/items/{product_id}/carton-quantity
```

请求在原有 `request_id`、`operation` 和 `quantity` 基础上增加必填 `reason_type` 及按规则填写的 `reason_note`。后端生成最终中文原因并追加 `ADJUST` 事件。调整成功后，如果已有来源分配与新数量不一致，保留来源记录但将该品规标记为“待重新分配”，完成校验不通过；前端明确显示差额。

### 5.5 完成批次

```text
POST /api/v1/scan-sessions/{session_id}/complete
```

请求包含 `confirm_exceptions`。后端在事务中锁定批次和全部汇总行，并重新校验：

- 批次存在且用户有写权限；
- 所有品规数量非负并按整包对齐；
- 至少存在一个有效品规；
- 每个品规来源分配与最终支数完全一致；
- 存在异常时 `confirm_exceptions` 必须为 `true`。

校验通过后设置 `status=COMPLETED` 和 `completed_at`。接口不要求当前模型中不存在的 `version` 字段；重复请求若批次已经完成，返回当前完成状态，不重复变更。

完成事务通过行锁与并发扫码、调整和来源保存互斥。先取得锁的请求成功，后续写请求重新读取状态并返回批次已关闭。

### 5.6 Excel 导出

```text
GET /api/v1/scan-sessions/{session_id}/export.xlsx
```

仅允许导出已完成且有权限查看的批次。后端从封存数据生成内存工作簿，计算文件大小和 SHA-256，写入 `export_records`，随后返回二进制内容。请求结束释放内存，不创建服务器文件。

文件名：

```text
涉案卷烟统计_{session_no}_{yyyyMMdd_HHmmss}.xlsx
```

响应 MIME：

```text
application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
```

## 6. 前端设计

### 6.1 来源分配抽屉

现有品规数量表不增加列，避免横向滚动。在“操作”列中纵向展示“来源分配”和“删除”。完成后按钮改为“查看来源”，删除按钮隐藏或禁用。

来源抽屉展示：

- 品规名称和条码；
- 最终包数、折合条数和支数；
- 已分配及未分配数量；
- 来源类型、省市级联选择和分配包数；
- 已添加来源明细；
- 保存和取消操作。

省市控件按照来源类型锁定、隐藏或过滤。相同来源在页面和后端均合并。只有分配总量与品规最终数量一致时允许保存。

### 6.2 调整原因确认

点击增加、减少或确认设置数量后打开轻量确认框。原因必填，“其他”必须填写备注。确认成功后刷新后端权威状态、来源分配差额和操作流水。

### 6.3 完成区域

工作台底部增加完成卡片，展示：

- 品规数量；
- 折合条数、总包数和总支数；
- 参考零售价合计；
- 来源地分配进度；
- 未识别和未解决歧义数量。

来源未全部匹配时禁用完成按钮并指出具体未分配品规。完成弹窗展示最终汇总；存在异常时使用醒目提示并要求勾选确认。

完成成功后页面立即切换为只读状态，扫码输入、调整、删除、来源编辑和歧义处理不可用，同时显示 Excel 下载入口。

## 7. Excel 工作簿

工作簿固定包含四张表：

1. `卷烟登记表`；
2. `品规汇总`；
3. `操作流水`；
4. `异常编码`。

### 7.1 卷烟登记表

顶部批次信息包含：

- 标识；
- 承办单位；
- 立案编号；
- 累计扫描数量，显示折合条数和总支数；
- 累计零售价合计。

来源明细列固定为：

| 序号 | 品规名称 | 条形码 | 品牌 | 类型 | 条支比 | 零售价（条） | 查获数量（条） | 查获数量（支） | 卷烟来源地类型 | 来源省 | 来源市 |
|---:|---|---|---|---|---:|---:|---:|---:|---|---|---|

每条来源记录完整重复品规字段，不合并单元格、不省略重复值，以便筛选、统计和后续系统读取。

### 7.2 品规汇总

每个条码品规一行，至少包含序号、品牌、品规名称、条码、条支比、每包支数、条零售价、最终包数、折合条数、总支数和参考金额。

### 7.3 操作流水

按时间顺序导出扫描、歧义处理和人工调整事件，包含时间、事件类型、结果、原始编码、品规快照、单位、数量变化、操作人和原因。历史扫码流水不因调整或品规删除而消失。

### 7.4 异常编码

导出未识别编码和未解决歧义编码，包含编码、异常类型、候选品规、发生时间和处理状态。已解决歧义在操作流水中体现，不重复列为未解决异常。

### 7.5 Excel 格式

- 条码和异常编码单元格强制使用文本格式，禁止科学计数法；
- 金额保留两位小数；
- 条数最多保留一位小数，支数和包数为整数；
- 时间显示为 `yyyy/mm/dd hh:mm:ss`，按中国标准时间输出；
- 表头冻结、自动筛选、合理列宽和打印区域；
- 工作簿元数据写入模板版本和生成时间；
- Excel 汇总必须与完成批次数据库结果一致。

## 8. 权限

- `ADMIN`：查看、核对、完成和导出全部分局批次；
- `OPERATOR`：只操作和导出所属分局批次；
- `VIEWER`：只查看和导出权限范围内的已完成批次；
- 写操作统一要求批次为 `DRAFT`；
- 下载接口重新执行服务端权限校验，不依赖前端按钮是否可见。

## 9. 错误处理

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `SCAN_SESSION_CLOSED` | 409 | 批次已完成，禁止修改 |
| `QUANTITY_NOT_PACK_ALIGNED` | 422 | 数量不是整包 |
| `ADJUSTMENT_REASON_REQUIRED` | 422 | 人工调整原因缺失或不完整 |
| `SOURCE_LOCATION_INVALID` | 422 | 来源类型和省市组合不合法 |
| `SOURCE_QUANTITY_MISMATCH` | 422 | 本次来源列表合计与品规数量不一致 |
| `SOURCE_ALLOCATION_REQUIRED` | 409 | 存在未完成来源分配的品规 |
| `EXCEPTION_CONFIRMATION_REQUIRED` | 409 | 存在异常但未明确确认 |
| `EXPORT_SESSION_NOT_COMPLETED` | 409 | 进行中批次不能导出 |
| `EXPORT_EMPTY` | 422 | 批次没有有效品规数据 |

错误响应继续使用统一错误码、用户提示和 `trace_id`，不暴露内部堆栈。

## 10. 并发与一致性

- 数量调整继续使用唯一 `request_id`、事务和行锁保证幂等；
- 来源整体保存锁定批次和品规汇总，以最后一次成功保存的完整集合为权威；
- 完成操作锁定批次和全部品规汇总，在持锁事务中重新读取并校验全部来源；
- 完成与扫码、调整或来源保存并发时，只允许先获得有效锁且通过状态校验的操作成功；
- Excel 只读取 `COMPLETED` 批次，不读取浏览器缓存或本地状态；
- `scan_events` 只追加，`scan_session_items` 和来源分配提供实时权威结果。
