# 阶段 8：简道云一键导入设计

## 1. 目标

在已完成盘点结果页面提供与 Excel 导出平级的“一键导入简道云”功能。后端根据当前批次最终核对结果生成一份不可变 JSON 快照，调用已联调通过的简道云新建单条数据接口，并永久记录该批次的导入状态和外部数据 ID。

本阶段面向约 50 名内网用户，采用单表、同步人工触发方案，不引入消息队列、后台任务或自动重试。

## 2. 已确认规则

- 只有 `COMPLETED` 批次可以导入；
- 管理员可以导入全部分局批次，操作员只能导入本分局批次；
- 同一批次只允许成功创建一条简道云数据；
- 成功后的重复请求直接返回原状态和外部数据 ID，不再次调用简道云；
- 首次点击生成不可变快照，明确失败后的人工重试继续发送同一份快照；
- 成功导入后即使本系统结果被修订，也不自动覆盖或再次导入；
- 简道云子表按最终品规汇总，一条码一行；同名不同条码平级显示；
- 来源地不传入简道云，继续保留在本系统和 Excel 中；
- 类型固定传“卷烟”，本阶段不改品规数据库；
- 数量按条传输，值为最终核对支数除以该品规条支比；
- API Key、真实接口地址、应用 ID 和表单 ID 只存在于后端运行环境，不进入前端、数据库、日志或 Git。

## 3. 页面交互

按钮位于已完成盘点详情的完成/导出操作区域，与“导出 Excel”平级。

| 状态 | 按钮 | 行为 |
|---|---|---|
| 未导入 | `一键导入简道云` | 可点击，点击后先二次确认 |
| `PENDING` | `正在导入…` | 禁用，防止重复提交 |
| `SUCCEEDED` | `已导入` | 禁用；悬停提示“该盘点批次已经导入简道云，不能重复导入。” |
| `FAILED` | `重新导入` | 可点击，重试原不可变快照 |
| `UNCERTAIN` | `导入结果待核查` | 禁用，提示按标识 ID 到简道云人工核查 |

成功后页面显示导入时间和外部数据 ID。失败只显示后端返回的脱敏原因，不显示鉴权信息或完整外部响应。页面刷新后从数据库重新读取状态。

正常外部调用最长约 25 秒。若应用进程在请求期间退出，状态可能停留在 `PENDING`；查询或再次操作时发现 `PENDING` 已超过 120 秒，后端将其转为 `UNCERTAIN`，要求人工核查，不自动再次发送。

## 4. 数据模型

新增 `integration_snapshots` 表，同一 `session_id` 只能存在一行。

| 字段 | MySQL 类型 | 约束与含义 |
|---|---|---|
| `id` | BIGINT UNSIGNED | 主键、自增 |
| `session_id` | BIGINT UNSIGNED | 唯一外键，关联 `scan_sessions.id` |
| `payload_json` | JSON | 首次导入时生成的不可变业务 `data` 快照，不含接口配置和鉴权信息 |
| `payload_sha256` | CHAR(64) | 规范化 JSON 的 SHA-256 |
| `status` | VARCHAR(16) | `PENDING`、`SUCCEEDED`、`FAILED`、`UNCERTAIN` |
| `external_data_id` | VARCHAR(100) | 简道云返回的数据 ID，可空 |
| `attempt_count` | INT UNSIGNED | 实际外部调用次数 |
| `last_error_code` | VARCHAR(64) | 最近一次脱敏错误分类，可空 |
| `last_error_message` | VARCHAR(500) | 最近一次脱敏错误摘要，可空 |
| `created_by` | BIGINT UNSIGNED | 首次生成快照的用户 |
| `last_attempted_by` | BIGINT UNSIGNED | 最近执行导入的用户 |
| `created_at` | DATETIME(6) | UTC 创建时间 |
| `updated_at` | DATETIME(6) | UTC 最近更新时间 |
| `succeeded_at` | DATETIME(6) | UTC 成功时间，可空 |

表使用 InnoDB、`utf8mb4` 和现有命名规范。建表由独立 SQL 完成；执行前必须备份并取得用户逐次批准，不使用 Alembic，不在应用启动时执行 DDL。

## 5. 简道云字段映射

### 5.1 主表

| 简道云字段 | 本系统来源 |
|---|---|
| 标识 ID | 批次当前 `display_label` |
| 县（分）局 | `branch_name` |
| 立案编号 | `filing_case_no`，未填写传空字符串 |
| 登记人员 | 原批次 `operator_name` |
| 登记卷烟列表 | 最终品规汇总子表 |

### 5.2 子表

| 简道云字段 | 本系统来源 |
|---|---|
| 条包装条形码 | `product_snapshot.carton_code` |
| 品规名称 | `product_snapshot.standard_name` |
| 品牌 | `product_snapshot.brand` |
| 类型 | 固定为“卷烟” |
| 条支比 | `product_snapshot.sticks_per_carton` |
| 入库数量（条） | `total_sticks / sticks_per_carton` |

条码按 JSON 字符串发送；条支比和条数按 JSON number 发送。只发送最终数量大于零的品规，顺序与品规统计表一致。来源拆分、价格、扫码流水和异常编码不进入简道云表单。

## 6. 后端结构与数据流

正式功能复用 Excel 导出的权威数据查询，但不生成 Excel、不写 `export_records`。数据库只保存表单业务 `data`，调用时再使用运行环境中的应用 ID、表单 ID 和开关组装完整请求。简道云请求构造和 HTTP 客户端放在独立集成服务中，API 控制器只负责鉴权、Origin 校验和响应封装。

```text
POST 一键导入
  → 校验配置、权限、COMPLETED 和非空结果
  → 锁定批次并读取 integration_snapshots
  → 已成功：直接返回原记录
  → 正在处理或结果不确定：拒绝再次调用
  → 首次：构造快照、摘要并保存 PENDING
  → 明确失败重试：复用原 payload_json，改为 PENDING
  → 提交本地事务
  → 单次调用简道云，不自动重试
  → 新事务保存 SUCCEEDED、FAILED 或 UNCERTAIN
```

外部网络调用不占用数据库事务。`session_id` 唯一约束和行锁共同防止并发点击重复创建。

超过 120 秒的 `PENDING` 视为进程中断后的不确定结果，转换为 `UNCERTAIN`；该转换不调用外部接口。

## 7. API 契约

### 7.1 查询状态

```text
GET /api/v1/scan-sessions/{session_id}/integration-snapshot
```

返回 `status`、`external_data_id`、`attempt_count`、脱敏错误、`created_at`、`updated_at` 和 `succeeded_at`；未生成时 `snapshot` 为 `null`。

### 7.2 一键导入

```text
POST /api/v1/scan-sessions/{session_id}/jiandaoyun-import
```

写接口必须登录、校验 Origin 和数据范围。响应字段与状态查询一致，并包含统一 `trace_id`。

### 7.3 错误码

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `INTEGRATION_NOT_CONFIGURED` | 409 | 后端简道云配置不完整 |
| `INTEGRATION_SESSION_NOT_COMPLETED` | 409 | 批次尚未完成 |
| `INTEGRATION_EMPTY` | 422 | 批次没有有效品规 |
| `INTEGRATION_IN_PROGRESS` | 409 | 当前批次正在导入 |
| `INTEGRATION_UNCERTAIN` | 409 | 上次结果不确定，需要人工核查 |
| `INTEGRATION_EXTERNAL_REJECTED` | 502 | 简道云明确拒绝，已记录为 `FAILED` |
| `INTEGRATION_EXTERNAL_UNCERTAIN` | 502/504 | 外部结果不确定，已记录为 `UNCERTAIN` |

## 8. 外部错误分类

- HTTP 2xx 且存在 `data._id`：`SUCCEEDED`；
- HTTP 4xx：`FAILED`，允许人工重试；
- 网络异常、连接中断、超时、HTTP 5xx：`UNCERTAIN`；
- HTTP 2xx 但非 JSON 或缺少 `data._id`：`UNCERTAIN`；
- 任意失败均不得回滚、修改或删除盘点数据。

真实调用使用 `Authorization: Bearer <API Key>`、UTF-8 JSON、连接超时 5 秒和读取超时 20 秒，不自动重试，不启动外部工作流或触发器。

## 9. 配置与秘密保护

后端环境变量：

```text
JIANDAOYUN_CREATE_URL
JIANDAOYUN_APP_ID
JIANDAOYUN_ENTRY_ID
JIANDAOYUN_API_KEY
```

四项必须完整配置才允许真实导入。`.env.example` 仅保留空白键名；版本文件中的真实地址、应用 ID、表单 ID 和 API Key 必须清理。日志仅记录批次 ID、状态、耗时、HTTP 状态和外部数据 ID，不记录请求头、Token、完整请求正文或完整外部响应。

## 10. 测试与验收

- 请求体主表、子表字段与已联调表单完全一致；
- 标识、分局、立案编号和原登记人取值正确；
- 一个条码对应一个子表行，同名不同条码平级；
- 入库数量是最终折合条数，条码为字符串、数量为 JSON number；
- 跨分局、未完成批次、空批次和配置缺失均被拒绝；
- 首次点击生成不可变快照，失败重试不重新读取已修订结果；
- 并发点击最多产生一次外部调用；
- 成功后的任何重复请求不再调用外部接口；
- 4xx、5xx、超时和异常响应按设计分类且不泄露秘密；
- 页面刷新后保持“已导入”禁用状态并提供悬停提示；
- 进程中断遗留的 `PENDING` 超过 120 秒后转为 `UNCERTAIN`，且不产生第二次外部调用；
- 后端、前端、OpenAPI、TypeScript、构建、Lint 和现有 E2E 回归通过；
- MySQL 容器重启后快照和导入状态仍存在；
- 自动测试只使用 Mock，正式实现完成后使用专门测试批次人工执行一次真实联调。

## 11. 范围外

- 自动推送和定时重试；
- 批量导入多个批次；
- 自动修改或删除简道云数据；
- 成功后重新推送本系统修订结果；
- `UNCERTAIN` 状态自动恢复；
- 来源地、价格、流水和异常编码推送；
- 雪茄分类；
- 消息队列、Redis、微服务或单独接口记录页面。
