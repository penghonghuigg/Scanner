# 阶段 5D：品规删除与表格对齐设计

**批准日期：** 2026-09-01
**状态：** 已实施并通过验证

## 1. 目标

修正扫码工作台品规数量表的表头与内容错位问题，放大表格文字，并为每个平铺品规行增加可追溯的删除操作。

## 2. 标准表格结构

- `ProductQuantityTable.vue` 使用标准 HTML `<table>`、`<thead>`、`<tbody>`、`<tr>`、`<th>` 和 `<td>`；
- 表头与内容使用同一列结构，不再使用 CSS Grid 模拟表格；
- 11 列顺序保持为：序号、品牌、卷烟名称（标准品规）、已扫描条码、条码后 6 位、类型、条支比、零售价、数量（条）、金额小计、操作；
- 所有表头和单元格水平、垂直居中；
- 表头字号约 13px，普通内容约 14px，卷烟名称约 15px 加粗，条码使用 13px 等宽字体；
- 桌面端设置稳定的列宽；窄屏保留横向滚动，不改成卡片或版本结构；
- 数量栏继续提供 `− / 输入 / + / 确认`，步进固定为 0.1 条。

## 3. 删除业务含义

删除表示“从当前批次统计中移除该品规”，不是删除原始扫码证据：

1. 用户点击行内“删除”按钮；
2. 前端弹出确认框，显示标准品规名称和条码；
3. 用户确认后提交带唯一 `request_id` 的删除请求；
4. 后端锁定 `DRAFT` 批次和目标汇总行；
5. 追加一条 `ADJUST/SUCCESS` 事件，`delta_sticks` 等于当前 `total_sticks` 的相反数，`reason` 固定为“删除品规统计：数量归零并隐藏”；
6. 删除当前 `scan_session_items` 汇总行，使其立即从统计表隐藏；
7. 原有 `SCAN`、`RESOLVE`、`ADJUST` 事件及新增删除事件全部保留；
8. 以后重新扫描相同条码时，系统重新创建汇总行并从新扫码数量开始统计。

删除事件保留原汇总行的 `product_snapshot`，因此历史流水仍能展示名称、条码和价格。删除后批次总品规数、总支数和参考金额均由最新状态重新计算。

## 4. API 契约

```http
POST /api/v1/scan-sessions/{session_id}/items/{product_id}/remove
```

请求：

```json
{
  "request_id": "UUID"
}
```

响应沿用 `ScanOperationResponse`，返回删除事件、删除后的 `ScanStateResponse` 和 `idempotent_replay`。

幂等规则：

- 首次请求追加事件并删除汇总行；
- 相同 `request_id` 重放时，即使汇总行已经不存在，也返回原删除事件和当前状态；
- 同一请求号被其他批次、产品或其他事件类型使用时返回 `409 IDEMPOTENCY_CONFLICT`；
- 使用新的请求号再次删除已不存在的行时返回 `404 SCAN_SESSION_ITEM_NOT_FOUND`。

## 5. 权限与确认

- `ADMIN` 和具有当前批次写权限的 `OPERATOR` 可以删除；
- `VIEWER`、越权分局用户或非 `DRAFT` 批次不能删除；
- 删除按钮在只读状态下禁用；
- 删除前必须二次确认；取消确认不发送请求；
- 请求进行中禁用该行数量及删除控件，防止重复操作；
- 网络失败时保留本次删除 `request_id`，再次确认同一行时复用请求号。

## 6. 数据与事务

- 不新增数据库表、字段、索引或迁移；
- `scan_events` 继续只追加；
- `scan_session_items` 是可重建的实时汇总，本操作允许删除目标汇总行；
- 在同一事务中完成批次锁、汇总行锁、幂等检查、删除事件追加和汇总行删除；
- 删除事件的 `unit_type` 使用 `STICK`，准确表达本次按总支数归零；
- `delta_sticks` 必须小于等于 0；总支数为 0 的行仍可删除，事件变化量为 0。

## 7. 测试与验收

1. 服务层测试覆盖删除后汇总行不存在、事件保留、负向 `delta_sticks`、快照完整、重新扫码重建和事务持久化；
2. 测试覆盖幂等重放、请求号冲突、并发删除、目标不存在、VIEWER、越权和关闭批次；
3. API/OpenAPI 测试覆盖新路径、请求字段、响应和错误码；
4. 前端测试覆盖标准 `<table>`、11 列严格对齐、放大字号类、删除确认、取消、成功、失败重试和只读禁用；
5. E2E 覆盖真实扫码、删除、流水留痕、行消失、重新扫描后重新出现；
6. 运行后端、前端、Ruff、ESLint、构建、全部 E2E、Compose 和 Git 范围审计；
7. 未实现批量删除、撤销删除、清空盘点或物理删除扫码流水。

## 8. 完成定义

表头与数据列严格对齐，字号清晰；删除按钮只在授权场景可用；确认删除后当前行消失、汇总同步变化、历史流水完整保留；重新扫码可以恢复该品规；所有验证通过；不执行 DDL、Git 提交或推送。
