# 涉案卷烟智能统计系统生产服务器部署手册

## 1. 适用范围

本手册适用于在现有 Debian 11 服务器上首次部署本系统。系统使用独立的 `scanner-web`、`scanner-api` 和 `scanner-mysql` 容器，通过已有 Caddy 提供公网 HTTPS 入口。

首次上线只保留：

- 初始管理员 `phh_admin`；
- 本地现有的 `cigarette_products` 品规数据；
- 全新的其他业务表。

不迁移用户、批次、扫码流水、导出记录或简道云导入记录。

> 禁止执行 `docker compose down -v`，禁止删除 `scanner_mysql_data` 卷。现有 Caddy、PostgreSQL、Redis、sub2api 和 image-api-site 容器不得停止或删除。

## 2. 发布前准备

准备以下内容，但不要把真实密码、Token、服务器 IP 或数据库备份提交到 Git：

1. 经批准的 Git 发布标签，例如 `v1.0.0`；
2. 本地品规 SQL 文件及 SHA-256；
3. 简道云四项生产配置；
4. 阿里云安全组和现有 Caddy 管理权限。

## 3. 服务器预检查

在服务器 SSH 会话执行：

```bash
docker version
docker compose version
docker ps --format 'table {{.Names}}\t{{.Ports}}'
docker system df
df -h /
free -h
docker network inspect scanner_proxy
```

`scanner_proxy` 首次不存在时可以继续；其他命令应成功。构建前建议保留至少 3 GiB 可用磁盘。清理 Docker 构建缓存或 systemd journal 前必须单独确认，不在本手册中自动执行。

## 4. 创建目录和代理网络

```bash
install -d -m 0750 /opt/scanner/app /opt/scanner/config /opt/scanner/import /opt/scanner/backups
docker network inspect scanner_proxy >/dev/null 2>&1 || docker network create scanner_proxy
```

再次确认现有 Caddy 容器名为 `caddy`。

## 5. 从 GitHub 检出固定版本

`/opt/scanner/app` 必须为空目录。以下的 `v1.0.0` 只是发布标签示例，必须替换为当次已批准标签：

```bash
git clone https://github.com/penghonghuigg/Scanner.git /opt/scanner/app
cd /opt/scanner/app
git fetch --tags --prune
git checkout --detach v1.0.0
git rev-parse HEAD
```

记录输出的提交 SHA。不得在服务器上直接修改 Git 跟踪文件。

## 6. 生成生产环境配置

下列命令通过环境变量生成文件，不会把密码字面量留在 shell 历史中。不要把屏幕输出或 `.env` 发到聊天或 GitHub。

```bash
umask 077
SCANNER_VERSION='v1.0.0'
MYSQL_DATABASE='scanner'
MYSQL_USER='scanner'
MYSQL_PASSWORD="$(openssl rand -hex 24)"
MYSQL_ROOT_PASSWORD="$(openssl rand -hex 24)"
read -rp 'HTTPS 公网来源（例如 https://公网IP）: ' ALLOWED_ORIGINS
read -rp '简道云创建接口 URL: ' JIANDAOYUN_CREATE_URL
read -rp '简道云 App ID: ' JIANDAOYUN_APP_ID
read -rp '简道云 Entry ID: ' JIANDAOYUN_ENTRY_ID
read -rsp '简道云 API Key: ' JIANDAOYUN_API_KEY; printf '\n'

{
  printf 'SCANNER_VERSION=%s\n' "$SCANNER_VERSION"
  printf 'MYSQL_DATABASE=%s\n' "$MYSQL_DATABASE"
  printf 'MYSQL_USER=%s\n' "$MYSQL_USER"
  printf 'MYSQL_PASSWORD=%s\n' "$MYSQL_PASSWORD"
  printf 'MYSQL_ROOT_PASSWORD=%s\n' "$MYSQL_ROOT_PASSWORD"
  printf 'DATABASE_URL=mysql+pymysql://%s:%s@scanner-mysql:3306/%s?charset=utf8mb4\n' "$MYSQL_USER" "$MYSQL_PASSWORD" "$MYSQL_DATABASE"
  printf 'APP_ENV=production\n'
  printf 'COOKIE_SECURE=true\n'
  printf 'SESSION_TTL_HOURS=8\n'
  printf 'ALLOWED_ORIGINS=%s\n' "$ALLOWED_ORIGINS"
  printf 'JIANDAOYUN_CREATE_URL=%s\n' "$JIANDAOYUN_CREATE_URL"
  printf 'JIANDAOYUN_APP_ID=%s\n' "$JIANDAOYUN_APP_ID"
  printf 'JIANDAOYUN_ENTRY_ID=%s\n' "$JIANDAOYUN_ENTRY_ID"
  printf 'JIANDAOYUN_API_KEY=%s\n' "$JIANDAOYUN_API_KEY"
} > /opt/scanner/config/.env

chmod 600 /opt/scanner/config/.env
unset MYSQL_PASSWORD MYSQL_ROOT_PASSWORD ALLOWED_ORIGINS JIANDAOYUN_CREATE_URL JIANDAOYUN_APP_ID JIANDAOYUN_ENTRY_ID JIANDAOYUN_API_KEY
```

不要在命令行打印 `.env` 内容。只检查权限和键名：

```bash
stat -c '%a %U:%G %n' /opt/scanner/config/.env
cut -d= -f1 /opt/scanner/config/.env
```

## 7. 导出并上传品规数据

在 Windows PowerShell 的项目根目录执行：

```powershell
docker compose --env-file .env -f compose.dev.yaml exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --no-create-info --skip-triggers --complete-insert --hex-blob "$MYSQL_DATABASE" cigarette_products > /tmp/cigarette_products.sql'
docker compose --env-file .env -f compose.dev.yaml cp mysql:/tmp/cigarette_products.sql ./backups/cigarette_products.sql
Get-FileHash -Algorithm SHA256 ./backups/cigarette_products.sql
```

输出文件必须只包含 `cigarette_products`。不得包含 `users`、`scan_sessions`、`scan_events`、`export_records` 或 `integration_snapshots`。

在当前 PowerShell 会话中设置服务器参数并上传：

```powershell
$SERVER_IP = Read-Host '服务器公网 IP'
$SSH_PORT = Read-Host 'SSH 端口'
scp -P $SSH_PORT ./backups/cigarette_products.sql "root@${SERVER_IP}:/opt/scanner/import/cigarette_products.sql"
```

上传后在服务器计算 `sha256sum /opt/scanner/import/cigarette_products.sql`，必须与本地结果一致。

## 8. 构建并初始化数据库

先验证 Compose：

```bash
cd /opt/scanner/app
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml config --quiet
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml build
df -h /
free -h
```

如剩余磁盘低于 3 GiB 或出现 OOM，立即停止，不继续启动。

只启动 MySQL：

```bash
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml up -d scanner-mysql
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml ps
```

等待 `scanner-mysql` 为 `healthy`，再显式建表：

```bash
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml run --rm --no-deps scanner-api python -m app.cli.init_db
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml run --rm --no-deps scanner-api python -m app.cli.init_db
```

两次都必须成功，用于验证初始化幂等性。

创建初始管理员，密码不回显且不写入 `.env`：

```bash
read -rsp '管理员密码: ' ADMIN_PASSWORD; printf '\n'
printf '%s\n' "$ADMIN_PASSWORD" | docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml run --rm --no-deps scanner-api python -m app.cli.create_user --username phh_admin --display-name 管理员 --role ADMIN --password-stdin
unset ADMIN_PASSWORD
```

检查品规表为空并导入一次：

```bash
sha256sum /opt/scanner/import/cigarette_products.sql
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml exec -T scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$MYSQL_DATABASE" -Nse "SELECT COUNT(*) FROM cigarette_products"'
```

查询结果必须为 `0`：

```bash
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml exec -T scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$MYSQL_DATABASE"' \
  < /opt/scanner/import/cigarette_products.sql

docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml exec -T scanner-mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$MYSQL_DATABASE" -Nse "SELECT COUNT(*), SUM(is_active = 1) FROM cigarette_products"'
```

如数量与本地不一致，停止上线，不得重复导入。

## 9. 启动应用

```bash
cd /opt/scanner/app
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml up -d scanner-api scanner-web
docker compose --env-file /opt/scanner/config/.env -f compose.prod.yaml ps
ss -lntp
```

三个容器最终都应为 `healthy`。宿主机不应新增 3306、8000、5173 或 8080 监听。

## 10. 接入现有 Caddy

先连接代理网络：

```bash
docker network inspect scanner_proxy
docker network connect scanner_proxy caddy
docker exec caddy getent hosts scanner-web
```

如已连接，`docker network connect` 可能提示 endpoint already exists，不得因此删除 Caddy 的其他网络。

备份 Caddyfile：

```bash
cp -a /home/caddy/Caddyfile "/home/caddy/Caddyfile.bak-$(date -u +%Y%m%d-%H%M%S)"
```

交互输入公网 IP 并追加站点：

```bash
read -rp '服务器公网 IP: ' SCANNER_PUBLIC_IP
if grep -Fq "https://${SCANNER_PUBLIC_IP} {" /home/caddy/Caddyfile; then
  printf 'Caddyfile 已存在该公网 IP 站点，停止追加\n' >&2
  unset SCANNER_PUBLIC_IP
  exit 2
fi

cat >> /home/caddy/Caddyfile <<EOF

https://${SCANNER_PUBLIC_IP} {
    tls {
        issuer acme {
            profile shortlived
        }
    }
    encode gzip zstd
    reverse_proxy scanner-web:80
}
EOF

unset SCANNER_PUBLIC_IP
```

校验后平滑加载：

```bash
docker exec caddy caddy validate --config /etc/caddy/Caddyfile
docker exec caddy caddy reload --config /etc/caddy/Caddyfile
docker logs --since 5m caddy
```

必须同时确认原有三个 Caddy 站点正常。任一原站点异常时，立即恢复最新的 `Caddyfile.bak-*`，再次执行 `validate` 和 `reload`。

## 11. 阿里云安全组

入方只允许：

- TCP 80；
- TCP 443；
- 现有 SSH 端口。

禁止对公网开放 3306、8000、5173、8080 和其他容器内部端口。安全组由用户在阿里云控制台修改。

## 12. 上线验收

依次检查：

1. HTTP 自动跳转 HTTPS，浏览器信任证书；
2. `https://<公网IP>/api/v1/health/live` 返回成功；
3. 公网无法访问 3306、8000 和 5173；
4. 管理员登录、品规数量和权限正确；
5. 注册测试操作员，新建批次，扫描已知和未知编码；
6. 进行 `0.1 条`调整和来源地拆分，完成批次并下载 Excel；
7. 错误登录限速、Secure/HttpOnly/SameSite Cookie 和安全响应头正确；
8. 重启本项目容器后，用户、品规、批次和导入状态仍存在。

真实简道云导入只能使用专门测试批次，并在执行前再次展示脱敏摘要、获得一次性批准。部署本身不自动调用外部接口。

## 13. 月度备份与隔离恢复验证

安装每月 1 日 03:00 的备份任务，保留最新 12 份：

```bash
chmod 0750 /opt/scanner/app/deploy/scripts/backup_mysql.sh
chmod 0750 /opt/scanner/app/deploy/scripts/restore_mysql.sh
install -m 0644 /opt/scanner/app/deploy/cron/scanner-monthly-backup /etc/cron.d/scanner-monthly-backup
/opt/scanner/app/deploy/scripts/backup_mysql.sh
ls -lh /opt/scanner/backups
gzip -t /opt/scanner/backups/scanner-*.sql.gz
```

恢复验证只能进入固定隔离库：

```bash
LATEST_BACKUP="$(find /opt/scanner/backups -maxdepth 1 -type f -name 'scanner-*.sql.gz' -printf '%T@ %p\n' | sort -rn | head -n1 | cut -d' ' -f2-)"
/opt/scanner/app/deploy/scripts/restore_mysql.sh "$LATEST_BACKUP" scanner_restore_verify
unset LATEST_BACKUP
```

核对隔离库的表数、管理员和品规数量。脚本不会删库；测试库清理必须另行确认目标确为 `scanner_restore_verify`，不得触碰正式库。

## 14. 更新和回滚

更新顺序固定为：

1. 运行升级前备份；
2. `git fetch --tags --prune`；
3. 检出用户批准的新标签；
4. 校验 Compose 并构建；
5. 启动应用容器；
6. 执行健康检查和业务回归。

回滚时只切换到上一个已批准 Git 标签，重新构建并启动 `scanner-api` 和 `scanner-web`。不删除、重建或清空 `scanner_mysql_data`。若新版包含经批准的显式 SQL，回滚前需根据当次发布说明单独评估数据库兼容性。

## 15. 故障停点

出现以下任一情况时停止上线，保留日志和现场，不重复导入或删除数据：

- Git 标签与批准提交 SHA 不一致；
- 品规 SQL 的 SHA-256 或导入数量不一致；
- MySQL、API 或 Web 无法达到 healthy；
- Caddy 配置校验失败、证书签发失败或原有站点异常；
- 公网意外暴露数据库或应用内部端口；
- 可用磁盘低于 3 GiB 或发生 OOM。

## 16. 已批准的临时公网 HTTP 部署

仅在用户明确接受明文 HTTP 风险时，才允许使用本节。此模式不接入 Caddy，不复用 HTTPS Compose，也不发布 MySQL 或 API 端口；仅 `scanner-web` 发布 TCP 80。登录密码和会话 Cookie 以明文传输，必须将云防火墙的 TCP 80 来源限制为单位办公网络公网 IP，并在具备域名后迁移回 HTTPS。

服务器使用 `compose.http.yaml` 和根目录忽略文件 `/opt/scanner/config/.env.http.production`。该文件必须包含：

```text
APP_ENV=production
COOKIE_SECURE=false
ALLOW_INSECURE_HTTP=true
ALLOWED_ORIGINS=http://<公网IP>
```

`ALLOW_INSECURE_HTTP=true` 是唯一允许生产环境关闭 Secure Cookie 的显式开关；缺少该开关时 API 必须拒绝启动。启动和验收使用：

```bash
docker compose --env-file /opt/scanner/config/.env.http.production -f compose.http.yaml config --quiet
docker compose --env-file /opt/scanner/config/.env.http.production -f compose.http.yaml up -d
curl -fsS http://127.0.0.1/healthz
```

验收时还必须确认 `docker ps` 中只有 Web 容器出现 `0.0.0.0:80->80/tcp`，而 MySQL 和 API 没有宿主机端口映射。后续切换 HTTPS 时，停止 HTTP Compose 的应用容器，保留命名卷 `scanner_mysql_data`，恢复 `compose.prod.yaml` 与 `COOKIE_SECURE=true`；不得执行 `down -v`。

HTTP 模式的月度备份必须安装专用任务，不能安装默认 HTTPS 任务：

```bash
install -m 0644 /opt/scanner/app/deploy/cron/scanner-monthly-backup-http /etc/cron.d/scanner-monthly-backup
```

`backup_mysql.sh` 和 `restore_mysql.sh` 可以通过 `SCANNER_COMPOSE_FILE` 与 `SCANNER_ENV_FILE` 指向 HTTP 配置；不传入时仍使用原 HTTPS 默认值。
