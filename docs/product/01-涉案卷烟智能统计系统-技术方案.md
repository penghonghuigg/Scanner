# 涉案卷烟智能统计系统技术方案

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 项目名称 | 涉案卷烟全流程智能统计系统的研发与应用 |
| 文档版本 | V1.0 |
| 适用阶段 | 方案设计、立项评审、研发启动 |
| 部署形态 | 单位内网、Docker Compose |
| 数据库 | MySQL 8.x（InnoDB、utf8mb4） |

## 2. 建设背景

当前涉案卷烟在查处登记、入库、盘点和数据汇总过程中，主要依赖人工识别品规、登记数量和制作台账，存在效率低、易错、品规名称不统一以及流转信息难追溯等问题。

现有原型已经验证以下技术可行性：

- USB 扫码枪能够以键盘输入方式采集编码；
- 浏览器能够接收扫码枪的数字编码，并在扫码枪发送回车后识别、累计数量；
- 同品规可以合并统计，并保留扫码流水；
- 现有卷烟基础表包含条码、包码、品牌、品规、价格和条支比等信息。

正式系统需要将浏览器本地存储升级为统一的后端服务和数据库，并增加用户权限、审计、Excel 导出、集中备份及后续系统对接能力。

## 3. 建设目标

1. 建立统一、可维护的卷烟品规基础数据库。
2. 支持扫码枪扫描条码或包码并自动识别品规。
3. 以扫描批次为边界，实时累计条、包和总支数。
4. 保存每一次扫描及人工调整记录，保证可查询、可核对、可追溯。
5. 按统一模板生成真正的 `.xlsx` 统计文件。
6. 支持将已完成盘点结果生成不可变快照并一键导入简道云罚没烟登记表。
7. 采用 Docker Compose 部署，降低安装、升级和备份难度。

## 4. 建设范围

### 4.1 本期范围

- 用户登录及角色权限；
- 卷烟品规 Excel 导入、查询、启停和异常校验；
- 扫描批次创建、扫码登记、实时汇总、调整和完成；
- 未识别编码和歧义包码处理；
- 批次查询、扫码流水查询和审计日志；
- Excel 汇总、明细、流水和异常清单导出；
- 可选生成罚没烟登记快照并一键导入简道云；
- Docker Compose 部署、日志和数据库备份。

### 4.2 本期不包含

- 完整的仓库库位、调拨、出库和结存管理；
- 罚没烟管理系统内部功能；
- 罚没烟管理系统内部的后续审批、库存和处置流程；
- 面向公网或移动互联网的部署；
- 复杂审批流、电子签章和执法文书管理。

## 6. 核心业务设计

### 6.1 基础品规库

现有 Excel 数据导入到单表 `cigarette_products`，一行代表一个可扫码识别的品规版本，每行只有一个唯一条码及一个可空包码。导入时执行：

- `-1`、空字符串等无效包码统一转为空值；
- 条码、包码按字符串保存，禁止使用数值类型；
- 校验编码格式、品规名称、品牌、价格和条支比；
- 条码重复时阻止该行生效并生成错误报告；
- 包码重复时形成“歧义编码”，允许导入但扫码时必须人工选择；
- 导入结果直接返回成功数、失败数和错误原因，不保存导入任务文件。

### 6.2 扫描批次

一次案件登记或盘点对应一个扫描批次。批次记录业务类型、案件编号、地点、操作人、时间、备注和状态。状态包括：

```text
DRAFT（进行中） → COMPLETED（已完成）
```

已完成批次永久禁止继续扫码和处理歧义。管理员可修订全部已完成结果，同一县分局的操作员可共同修订本分局结果；查看员保持只读。修订可以从启用品规库按名称或条码后 6 位加入品规，或修改、删除现有品规及来源，后端以事务、行锁、`request_id` 和追加调整流水保证结果一致且可追溯。

用户导航将进行中记录命名为“盘点作业”，将已完成记录命名为“盘点结果”；数据库及 API 内部仍使用 `scan_sessions`、`DRAFT` 和 `COMPLETED`。

### 6.3 扫码识别

- 扫描条码：默认增加 1 条；
- 扫描包码：默认增加 1 包；
- 操作员以“包”为最小业务单位（1 包 = 0.1 条），数据库以整数支数保存和校验；
- 每次扫描生成唯一请求号，后端使用幂等约束防止网络重试导致重复计数；
- 同一品规的多个编码统一合并到同一统计项；
- 未识别编码进入异常清单；
- 歧义包码展示候选品规，操作员选择后才计数，并保存选择结果。

```text
总支数 = 条扫描数 × 每条支数 + 包扫描数 × 每包支数 + 人工调整支数
参考金额 = 总支数 ÷ 每条支数 × 条参考零售价
```

### 6.4 数据追溯

系统同时保存：

- 原始扫码流水；
- 品规汇总结果；
- 人工调整事件；
- 未识别及歧义处理记录；
- 导出记录；
- 批次状态变化记录；
- 接口推送记录。

扫码流水原则上只追加、不覆盖。汇总数据可重新从流水计算，用于核对数据一致性。

## 7. 数据架构

| 数据表 | 职责 |
|---|---|
| `users` | 用户、密码摘要、角色和状态 |
| `cigarette_products` | 标准卷烟品规 |
| `scan_sessions` | 扫描批次 |
| `scan_events` | 每一次扫描或调整事件 |
| `scan_session_items` | 批次内按品规形成的实时汇总 |
| `scan_item_source_allocations` | 按品规、来源类型、省市拆分的包数与支数 |
| `export_records` | Excel 导出记录 |
| `integration_snapshots` | 简道云登记快照、导入状态和外部数据 ID |
| `audit_logs` | 关键操作审计日志 |

数据库统一使用 InnoDB，字符集使用 `utf8mb4`，时间保存为 UTC，前端按中国标准时间展示。金额使用 `DECIMAL`，业务编号和条码使用字符类型。

## 9. Excel 导出

每个批次导出一个 `.xlsx` 文件，默认包含：

1. 卷烟登记表；
2. 品规汇总；
3. 操作流水；
4. 异常编码。

卷烟登记表按“品规 × 来源地”逐行展开，包含条数和支数。编码列强制设置为文本格式，金额使用两位小数。仅允许已完成批次导出；工作簿在内存中即时生成并返回，不在服务器保存文件，只在 `export_records` 保存文件名、大小、SHA-256、模板版本、操作人和生成时间。

## 10. 简道云罚没烟登记

已完成批次可由管理员或权限范围内的操作员手动生成一次不可变 JSON 快照，并同步调用简道云新建单条数据接口。每个批次只有一份快照和一条成功的外部登记，成功后的重复请求直接返回原外部数据 ID，不再次调用外部接口。

导入流程：

```text
完成批次 → 点击一键导入 → 保存不可变快照 → 调用简道云
        → 成功并保存外部数据 ID，按钮变为“已导入”
        → 明确拒绝后人工重试原快照
        → 超时或结果不确定时按标识 ID 人工核查
```

主表发送批次标识、县（分）局、立案编号和原登记人员；子表按最终品规汇总发送条码、品规名称、品牌、固定类型“卷烟”、条支比和折合条数。同名不同条码分别发送，来源地继续只保留在本系统和 Excel。外部接口失败不得回滚或破坏本地盘点结果。

接口地址、应用 ID、表单 ID 和 API Key 全部由后端环境变量注入，不写入版本文件、数据库、前端或日志。外部调用采用短超时且不自动重试；网络超时、HTTP 5xx 或成功响应缺少外部数据 ID 时标记为结果不确定，禁止直接再次发送。

## 11. 安全与权限

| 角色 | 权限 |
|---|---|
| 管理员 | 用户、基础库、导入、配置、全部查询和审计 |
| 操作员 | 创建批次、扫码、调整、完成和导出 |
| 查看员 | 查询已完成批次和下载报表 |

安全要求包括：

- 仅部署在受控内网；
- 密码使用强哈希算法保存；
- 登录状态放入 Secure、HttpOnly Cookie；
- 所有写操作进行权限校验；
- 上传文件限制大小、扩展名和内容；
- 数据库不暴露到公网；
- 敏感配置通过 `.env` 或 Docker Secret 注入；
- 登录、调整、删除、作废、导出和推送全部审计。

## 12. Docker 部署

```text
docker-compose.yml
├─ nginx      前端静态文件和反向代理
├─ api        FastAPI 后端
├─ mysql      MySQL 数据库
└─ backup     定时备份任务
```

持久化卷包括 MySQL 数据、导出文件、备份文件和应用日志。数据库每日自动备份，保留周期通过环境变量配置，并定期执行恢复演练。

## 13. 非功能目标

- 内网正常条件下，单次扫码接口 P95 响应时间不超过 500 ms；
- 10,000 条扫码流水的 Excel 导出时间不超过 10 秒；
- 合法且唯一的基础库编码识别准确率达到 100%；
- 同一幂等请求重复提交不得重复计数；
- 关键业务数据和审计日志不得因浏览器关闭而丢失；
- 服务重启后数据可恢复，数据库备份可验证还原；
- 支持主流 Chromium 内核浏览器和常见 USB 键盘模式扫码枪。

## 14. 实施阶段

1. 基础工程、MySQL、认证与权限；
2. 品规基础库、Excel 导入和编码识别；
3. 扫描批次、扫码流水和实时统计；
4. 异常处理、人工调整和审计；
5. Excel 模板导出；
6. Docker 部署、备份和试点；
7. 可选罚没烟登记快照及简道云一键导入。

## 15. 方案约束

- 系统默认运行在单位内网；
- 扫码枪采用键盘输入模式并以回车结束；
- 一次扫描批次是统计、完成和导出的基本边界；
- 本期只完成简道云罚没烟登记，不建设简道云内部后续业务；
- 本期不建设完整仓储管理系统。
