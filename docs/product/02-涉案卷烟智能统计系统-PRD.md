## 2. 产品背景

涉案卷烟登记和盘点通常需要人工辨认品规、填写名称、累计数量并制作报表。在品规多、数量大时，容易发生重复、遗漏、名称不规范和数量计算错误。系统通过扫描卷烟条码或包码，自动匹配标准品规、累计数量并形成可追溯流水，以降低人工工作量和差错率。

## 3. 产品目标

### 3.1 业务目标

- 将“人工辨认、手工登记、人工汇总”转变为“扫码识别、自动累计、模板导出”；
- 统一卷烟品规名称和基础属性；
- 支持案件登记、入库盘点和日常盘点等轻量场景；
- 使每次扫码、调整、导出和推送均可追溯；
- 为罚没烟管理系统提供可复用的数据登记入口。

### 3.2 成功指标

| 指标 | 验收目标 |
|---|---|
| 唯一有效编码识别准确率 | 100% |
| 扫码重复计数 | 同一请求重试时为 0 |
| 单次扫码响应 | 内网 P95 ≤ 500 ms |
| 10,000 条流水导出 | ≤ 10 秒 |
| 扫码及调整追溯 | 关键事件记录完整率 100% |
| 数据持久性 | 浏览器关闭或服务重启后不丢失已提交数据 |

## 4. 用户与角色

### 4.1 管理员

负责用户维护、品规数据导入、异常数据处理、系统配置、全量查询及审计。

### 4.2 操作员

负责创建扫描批次、扫码、处理未识别或歧义编码、调整数量、完成批次和导出报表。

### 4.3 查看员

负责查询已完成批次、查看统计结果和下载报表，不允许修改业务数据。

## 6. 核心概念

| 名称 | 定义 |
|---|---|
| 标准品规 | 统一维护的卷烟品牌、名称、价格和包装属性 |
| 条码 | 表示整条卷烟的编码，扫描一次增加一条 |
| 包码 | 表示单包卷烟的编码，扫描一次增加一包 |
| 扫描批次 | 一次案件登记或盘点活动的数据边界 |
| 扫码流水 | 每一次扫码、歧义选择或人工调整形成的不可覆盖记录 |
| 歧义编码 | 同一个编码匹配多个品规，必须人工选择后才能计数 |
| 幂等请求 | 同一请求重复提交不会重复增加数量 |

## 7. 业务流程

### 7.1 主流程

```text
登录
 → 新建扫描批次
 → 选择业务类型并填写案件信息
 → 扫描条码或包码
 → 自动识别并累计
 → 处理未识别或歧义编码
 → 核对/调整数量
 → 完成批次
 → 导出 Excel
 → 可选：一键导入简道云罚没烟登记表
```

### 7.2 编码识别分支

```text
唯一匹配 → 自动计数并反馈成功
无匹配   → 记录为未识别，不计入汇总
多个匹配 → 展示候选品规，人工选择后计数
```

| 编号 | 需求 |
|---|---|
| FR-STAT-001 | 页面实时展示累计折合条数、按标准名称去重的品规数、参考零售价合计和未识别次数。 |
| FR-STAT-002 | 品规明细使用单层平铺表格；每个批次汇总项一行，同名称不同条码显示为平级行，不展示版本分组。 |
| FR-STAT-003 | 操作员可以按当前行增加或减少固定 0.1 条，也可以直接设置非负且最多一位小数的条数；包码扫描数量保持不变。 |
| FR-STAT-004 | 每次 0.1 条人工调整必须选择“现场核对修正、扫码录入纠错、散包数量核对、其他”之一；选择“其他”时必须填写说明。 |
| FR-STAT-005 | 人工调整生成独立流水，不覆盖原扫码流水。 |
| FR-STAT-006 | 系统不得允许调整后总支数小于 0。 |
| FR-STAT-007 | 每行按自身总支数、每条支数和条零售价计算金额；同名称不同条码不在表格中合并金额。 |
| FR-STAT-010 | 平铺表格依次展示序号、品牌、标准品规、完整条码、类型、条支比、零售价、数量、金额小计和操作，共 10 列；完整条码最后 6 位红色加粗，表头与内容严格居中对齐，常用桌面宽度下不出现横向滚动条。 |
| FR-STAT-008 | 基础库提示展示启用状态下去重后的编码数和标准品规名称数。 |
| FR-STAT-009 | 固定按 `0.1 条 = 1 包` 调整；当前 200 支/条品规每次调整 20 支，数据库仍保存整数支数。 |
| FR-STAT-011 | 有写权限的用户可以在二次确认后从进行中作业或已完成结果中移除单个品规；查看员禁用删除。 |
| FR-STAT-012 | 删除品规只移除 `scan_session_items` 实时汇总，原扫码流水不得删除，并追加可追溯的负向 `ADJUST` 流水。 |
| FR-STAT-013 | 删除请求使用 `request_id` 保证幂等；网络失败后重试不得重复追加流水。 |
| FR-STAT-014 | 删除后再次扫描相同条码时重新创建汇总行，并从新扫描数量开始累计。 |
| FR-STAT-015 | 每个品规必须按包拆分来源，来源包数合计必须与最终数量完全一致后才能完成批次。 |
| FR-STAT-016 | 来源类型为外省流入、来源不详、市内串码、省内市外；外省流入必须选择非安徽省，来源市可选择具体城市并默认“不详”；市内串码固定安徽省淮南市，省内市外选择安徽省除淮南市外的市。 |
| FR-STAT-017 | 香港、澳门不进入来源目录；直辖市按省市同名处理；台湾按台湾省、台湾省处理。 |
| FR-STAT-018 | 完成前展示未识别和未解决歧义数量；允许带异常完成，但操作员必须显式二次确认。 |
| FR-STAT-019 | 左侧导航以“盘点作业”展示进行中记录，以“盘点结果”展示已完成记录；管理员在人员注册和品规管理页面也始终可见这两个入口。 |
| FR-STAT-020 | 权限范围内用户可在已完成结果中按品规名称或条码后 6 位查询启用品规，按最少 0.1 条加入，并同时登记完全匹配的来源。 |
| FR-STAT-021 | 已完成结果的数量和来源联合修订及品规删除必须追加操作流水，不覆盖原扫码流水；同一请求重试不得重复生效。 |

## 10. 交互要求

- 扫码页优先服务键盘和扫码枪，不要求鼠标操作；
- 成功后立即显示标准品规和累计数量；
- 未识别、歧义和系统错误不得只依赖颜色提示；
- 扫码处理期间防止重复提交；
- 网络失败时保留当前输入并允许重试；
- 清空、作废和完成操作必须二次确认；
- 批次关闭或无权限时，扫码输入框禁用并说明原因。

## 11. 数据与计算规则

1. 编码始终作为字符串保存。
2. 一条和一包的支数从扫码时对应的品规快照获取。
3. 历史批次不因基础库后续改价或改名而自动变化。
4. 金额为参考值，不作为财务结算凭证。
5. 汇总结果必须能够由扫码流水和调整流水重新计算。
6. 未识别编码不计入数量和金额。
7. 歧义编码在人工选择前不计入数量。

## 13. 验收场景

1. 导入现有基础数据，正确报告无效值、重复条码和重复包码。
2. 扫描唯一条码 10 次，汇总增加 10 条并产生 10 条流水。
3. 使用同一请求号重复提交，汇总只增加一次。
4. 扫描唯一包码，汇总增加一包并正确折算总支数。
5. 扫描重复包码，系统要求选择品规，未选择前不计数。
6. 扫描未知编码，异常次数增加，汇总不变。
7. 人工减少数量时填写原因，汇总和流水同步变化。
8. 完成批次后普通操作员不能继续扫码。
9. 导出的四个工作表数据与页面一致，编码不显示为科学计数法。
10. 已完成批次可一键导入简道云；成功后刷新页面仍显示不可点击的“已导入”，重复操作不产生新记录。
11. 重启 Docker 服务后，已提交批次和流水仍存在。
12. 无权限用户访问管理接口时返回拒绝结果并记录日志。

## 14. 发布边界

第一期发布完成扫码统计闭环以及简道云罚没烟登记。自动推送、批量导入、外部数据修改和简道云内部后续业务仍作为独立迭代实施。
