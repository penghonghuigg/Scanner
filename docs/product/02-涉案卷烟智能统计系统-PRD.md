# 涉案卷烟智能统计系统产品需求文档（PRD）

## 1. 产品说明

本系统用于约 50 名内部工作人员，通过扫码枪扫描涉案卷烟条码或包码，自动识别品规、累计数量并导出 Excel，减少手工登记和汇总错误。

系统按工作人员个人账号登录，每人归属田大分局、谢八分局、潘集分局、寿县局或凤台县局之一。同一分局允许多人同时登录和开展不同扫描批次。

## 2. 产品目标

- 扫码后快速识别卷烟品规和包装单位；
- 在一次扫描批次中自动累计条数、包数和总支数；
- 让未识别、歧义和人工调整过程可以核对；
- 按统一格式导出 Excel；
- 为后续罚没烟管理系统登记预留稳定的数据快照。

## 3. 用户与权限

| 用户 | 能力 |
|---|---|
| 管理员 | 登录、人员注册、品规维护、所有扫描和查询功能 |
| 操作员 | 登录、操作本人所属分局且由非管理员账号创建的扫描批次、导出和生成快照 |
| 查看员 | 兼容保留，只读查看本人所属分局且由非管理员账号创建的批次；当前不开放注册 |

管理员注册工作人员时必须填写账号、姓名、所属分局、初始密码和确认密码。新注册人员固定为操作员。

登录响应只返回用户身份、角色和所属分局，不返回独立权限数组。管理员功能判断角色，业务数据范围判断所属分局。

## 4. 主业务流程

```text
登录
 → 新建扫描批次
 → 选择业务类型并填写案件信息
 → 扫描条码或包码
 → 自动识别并累计
 → 处理未识别或歧义编码
 → 核对/调整数量
 → 完成批次
 → 导出 Excel
 → 可选：生成罚没烟系统推送快照
```

## 5. 功能需求

### 5.1 登录与人员

| 编号 | 需求 |
|---|---|
| FR-AUTH-001 | 用户使用个人账号和密码登录。 |
| FR-AUTH-002 | 登录状态由服务端会话维护，退出后当前会话失效。 |
| FR-AUTH-003 | 停用用户不得登录。 |
| FR-AUTH-004 | 页面入口按角色展示，接口在后端按角色和所属分局限制操作。 |
| FR-USER-001 | 管理员可以注册操作员。 |
| FR-USER-002 | 操作员必须归属五个固定分局之一。 |
| FR-USER-003 | 登录账号不得重复，新注册人员每人使用独立账号。 |

### 5.2 卷烟品规

| 编号 | 需求 |
|---|---|
| FR-PROD-001 | 管理员能够单条新增卷烟品规版本。 |
| FR-PROD-002 | 管理员能够下载 Excel 导入模板并批量导入现有品规数据。 |
| FR-PROD-003 | 导入前校验必填字段、编码、每条零售价和包装换算数量。 |
| FR-PROD-004 | `-1` 和空包码按无包码处理，`-1` 和空价格按未知价格处理。 |
| FR-PROD-005 | 一个品规版本只有一个唯一条码和零个或一个包码；同名但条码不同的记录是不同版本。 |
| FR-PROD-006 | 包码可以对应多个品规版本，查询时必须标记为歧义。 |
| FR-PROD-007 | 包码与任意条码冲突时，导入将包码清洗为空并给出警告。 |
| FR-PROD-008 | 管理员能够查询、修改、停用和重新启用品规版本。 |
| FR-PROD-009 | 系统保存每条参考零售价，并按每条包数计算每包参考零售价。 |

Excel 一行对应一个具体品规版本；重复导入相同条码时更新该版本，新条码即使名称相同也新增版本。有效行导入、错误行跳过，失败和警告信息直接展示并允许下载 CSV，不单独建设复杂的导入任务中心。

### 5.3 扫描批次与案件信息

| 编号 | 需求 |
|---|---|
| FR-BATCH-001 | 登录用户能够新建扫描批次。 |
| FR-BATCH-002 | 新建时必须选择市场检查、寄递渠道、专车运输或其他；立案编号、地点和备注均为选填。 |
| FR-BATCH-003 | 批次编号由系统自动生成且唯一。 |
| FR-BATCH-004 | 进行中批次可以继续扫码、处理异常和调整数量。 |
| FR-BATCH-005 | 已完成批次默认只读。 |
| FR-BATCH-006 | 管理员可操作全部批次；操作员和查看员只能访问本人分局且创建人不是管理员的批次。 |

### 5.4 扫码、识别与累计

| 编号 | 需求 |
|---|---|
| FR-SCAN-001 | 扫码输入框默认聚焦，只接受 13 位数字；扫码枪或人工输入达到 13 位后立即自动提交，尾随回车不得重复提交。 |
| FR-SCAN-002 | 唯一条码匹配时增加一条。 |
| FR-SCAN-003 | 唯一包码匹配时增加一包。 |
| FR-SCAN-004 | 同一品规的不同编码合并累计。 |
| FR-SCAN-005 | 每次提交携带唯一 `request_id`，重复请求不得重复计数。 |
| FR-SCAN-006 | 成功后显示品规、本次单位和当前累计数量。 |
| FR-SCAN-007 | 处理完成后清空输入并恢复焦点。 |
| FR-SCAN-008 | 每次扫码都保留原始编码、结果、操作人和时间。 |

### 5.5 未识别和歧义编码

| 编号 | 需求 |
|---|---|
| FR-EXCEPTION-001 | 未匹配编码进入未识别清单，不计入数量。 |
| FR-EXCEPTION-002 | 一个包码匹配多个品规时展示候选项。 |
| FR-EXCEPTION-003 | 操作员选择候选品规后才计数。 |
| FR-EXCEPTION-004 | 未识别和歧义状态必须有明确文字提示。 |
| FR-EXCEPTION-005 | 未识别编码本阶段只记录；管理员补充品规后，操作员使用新的请求号重新扫描。 |

### 5.6 核对、调整与完成

| 编号 | 需求 |
|---|---|
| FR-COUNT-001 | 页面展示品规数、条数、包数和总支数。 |
| FR-COUNT-002 | 操作员可以按品规增加或减少数量。 |
| FR-COUNT-003 | 人工调整必须填写原因并形成流水。 |
| FR-COUNT-004 | 调整后的数量不得小于零。 |
| FR-COUNT-005 | 完成前展示最终汇总并要求确认。 |
| FR-COUNT-006 | 批次完成后禁止继续扫码和调整。 |

### 5.7 Excel 导出

| 编号 | 需求 |
|---|---|
| FR-EXPORT-001 | 已完成批次可以导出 `.xlsx` 文件。 |
| FR-EXPORT-002 | 文件包含批次信息、品规汇总、操作流水和异常编码。 |
| FR-EXPORT-003 | 条码、包码按文本导出，不显示为科学计数法。 |
| FR-EXPORT-004 | 导出内容必须与批次最终数据一致。 |
| FR-EXPORT-005 | 文件名包含批次编号和导出时间。 |

### 5.8 罚没烟登记快照

| 编号 | 需求 |
|---|---|
| FR-SNAPSHOT-001 | 已完成批次可以手动生成 JSON 快照。 |
| FR-SNAPSHOT-002 | 快照包含批次、案件、单位、操作人和品规数量。 |
| FR-SNAPSHOT-003 | 快照生成后不可修改。 |
| FR-SNAPSHOT-004 | 本期不调用真实罚没烟接口，也不自动重试。 |

## 6. 页面范围

| 页面 | 主要内容 |
|---|---|
| 登录页 | 账号、密码和错误提示 |
| 工作台 | 当前用户、所属分局、快捷新建和最近批次 |
| 人员注册 | 管理员注册操作员 |
| 品规管理 | 单条新增、查询、编辑、停用、模板下载、批量导入和错误结果下载 |
| 新建批次 | 业务类型、选填立案编号、选填地点和选填备注 |
| 扫码页 | 扫码输入、最近结果、汇总、明细和异常 |
| 批次列表 | 按批次编号、立案编号、业务类型、状态和日期查询 |
| 批次详情 | 案件信息、汇总、流水、异常、导出和快照 |

## 7. 交互要求

- 扫码主流程无需鼠标即可连续完成；
- 成功、未知、歧义和错误使用文字及视觉状态共同反馈；
- 网络错误时保留当前输入，允许再次提交同一 `request_id`；
- 完成批次和人工减少数量需要明确确认；
- 前端展示后端返回的最终汇总，不自行计算权威数量；
- 前端页面保持简洁、清晰，适合日常内网业务使用。

## 8. 数据与质量要求

- 编码和业务编号均按字符串保存；
- 历史批次保存品规快照，不随基础库变更；
- MySQL 数据使用 Docker 命名卷持久化；
- 重启浏览器、前后端或容器后，已提交数据仍然存在；
- 所有写接口都需要登录和权限校验；
- 系统不在浏览器本地存储正式业务数据或登录密钥。

## 9. 核心验收场景

1. 管理员注册属于五个固定分局之一的操作员，操作员能够独立登录。
2. 登录用户新建批次并填写业务类型和案件信息。
3. 连续扫描唯一条码和包码，系统正确累计且保留流水。
4. 重复提交同一 `request_id`，数量只增加一次。
5. 未识别编码不计数，歧义包码选择品规后才计数。
6. 人工调整填写原因后，汇总和流水同步变化且数量不为负。
7. 完成批次后不能继续扫码或调整。
8. 导出的 Excel 与批次详情一致，编码不使用科学计数法。
9. 可选生成罚没烟登记快照，但系统不进行真实外发。
10. 重启 Docker MySQL 后业务数据仍存在。

## 10. 发布边界

第一期发布以“登录—批次—扫码—异常—核对—完成—Excel”闭环为完成标准。罚没烟功能只交付数据快照；真实接口联调在对方规范明确后另行批准和实施。
